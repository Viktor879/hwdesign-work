# Interface

The two AXI4-Stream ports have 64-bit TDATA, 8-bit TKEEP/TSTRB, TLAST and TVALID/TREADY, with no user/id/destination fields. Earliest elements occupy the least-significant lanes. Signed lanes use two's complement. Every output has KEEP=STRB=0xFF; input payload byte enables are ignored, but header byte enables must both equal 0xFF. **The delivered unregistered output has a known AXI compliance failure under backpressure; see Open Items.**

Each command header has three distinct words: opcode, transaction ID, unsigned parameter, each in the low 32 bits with zero upper padding, and TLAST sequence 0,0,1. CONFIG=1 accepts shift 0–15 and ten payload words: eight weight rows then two words containing four INT16 biases each. PROCESS=2 accepts count 1–32 and that many eight-lane INT8 vector words. END=3 requires parameter zero, has no payload, emits nothing, and ends the activation. Payload TLAST is set only on the expected final word. CONFIG/PROCESS acknowledge with a separately TLAST-terminated single word containing their own ID; PROCESS then emits its vector results, TLAST only on the last result. Legal IDs include zero and repeated values through 0xFFFFFFFE. 0xFFFFFFFF is the unavailable/reserved sentinel.

The generated AXI-Lite map is authoritative: control 0x00; GIER/IER/ISR 0x04/0x08/0x0C; read-only halted/error/tx_id at 0x10/0x20/0x30, with read-to-clear ap_vld bits at 0x14/0x24/0x34. The host waits for ap_done before interpreting final status. There are no coefficient or parameter registers. See [native register RTL](evidence/synthesis/qgemv_control_s_axi.v).

Error precedence is malformed header at the first bad word (1), unknown opcode (2), reserved ID (3), opcode-specific parameter (CONFIG shift/END parameter: 3; PROCESS count: 4), missing configuration (5), then early payload TLAST (6) or missing expected final TLAST (7). Word index 1 supplies a decodable ID when its upper padding and byte enables are valid, even if its TLAST is wrong. An unavailable/undecodable ID is the sentinel; every command starts with a fresh sentinel. Invalid headers/parameters stop without reading payload; payload errors stop exactly where observed, without a drain. Error status is (1,code,offending-ID). A successful activation keeps error status zero and returns (0,0,0), independent of END's ID. After an error the host discards/reset streams and starts a fresh activation.

# Design

The HLS kernel uses signed INT8 operands, INT16 products/biases and INT32 accumulation. Weights and biases are completely partitioned; row/column arithmetic is fully unrolled, expressing all 64 products for each vector. The compiler may map multipliers to DSP or fabric. Integer magnitude, half-unit addition, right shift and sign restoration implement ties away from zero; signed clipping precedes conversion to INT8.

One 32-word buffer receives and validates a complete payload before any response. CONFIG installs the whole buffered configuration atomically. PROCESS validates all vectors before responding, then a pipelined compute loop generates results in order. A validity flag, zero shift and cleared statuses begin every activation; physical weight RAM/register clearing is unnecessary. The command loop is sequential. Both stream register slices are disabled to prevent external prefetch. Blocking writes wait for readiness, but the generated output TVALID also waits for readiness, which violates the standard AXI source rule. This limitation is not waived.

The input receive and compute loops request II=1; the top command loop has no II target. Buffering costs a whole receive phase before computation/output, while unrolling and pipelining amortize that cost across a batch. No Python timing model was created. Timing below is extracted from actual external DUT transfers, using signal values before each rising clock edge; it is not inferred from loop counts or synthesis latency.
