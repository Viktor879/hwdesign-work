# Interface

The two AXI4-Stream ports have 64-bit TDATA, 8-bit TKEEP/TSTRB, TLAST and TVALID/TREADY, with no user/id/destination fields. Earliest elements occupy the least-significant lanes. Signed lanes use two's complement. Every output has KEEP=STRB=0xFF; input payload byte enables are ignored, but header byte enables must both equal 0xFF. **Current implementation: Run 2, Specification v1.** The production top is `src/qgemv.sv`, integrating the unmodified generated `qgemv_core` with an internal accepted-transfer counter. No feedback port or additional register is exposed to the host. Run 1 remains historical FAIL below.

Each command header has three distinct words: opcode, transaction ID, unsigned parameter, each in the low 32 bits with zero upper padding, and TLAST sequence 0,0,1. CONFIG=1 accepts shift 0–15 and ten payload words: eight weight rows then two words containing four INT16 biases each. PROCESS=2 accepts count 1–32 and that many eight-lane INT8 vector words. END=3 requires parameter zero, has no payload, emits nothing, and ends the activation. Payload TLAST is set only on the expected final word. CONFIG/PROCESS acknowledge with a separately TLAST-terminated single word containing their own ID; PROCESS then emits its vector results, TLAST only on the last result. Legal IDs include zero and repeated values through 0xFFFFFFFE. 0xFFFFFFFF is the unavailable/reserved sentinel.

The generated AXI-Lite map is authoritative: control 0x00; GIER/IER/ISR 0x04/0x08/0x0C; read-only halted/error/tx_id at 0x10/0x20/0x30, with read-to-clear ap_vld bits at 0x14/0x24/0x34. The host waits for ap_done before interpreting final status. There are no coefficient or parameter registers. See [native register RTL](evidence/run2/synthesis/qgemv_core_control_s_axi.v).

Error precedence is malformed header at the first bad word (1), unknown opcode (2), reserved ID (3), opcode-specific parameter (CONFIG shift/END parameter: 3; PROCESS count: 4), missing configuration (5), then early payload TLAST (6) or missing expected final TLAST (7). Word index 1 supplies a decodable ID when its upper padding and byte enables are valid, even if its TLAST is wrong. An unavailable/undecodable ID is the sentinel; every command starts with a fresh sentinel. Invalid headers/parameters stop without reading payload; payload errors stop exactly where observed, without a drain. Error status is (1,code,offending-ID). A successful activation keeps error status zero and returns (0,0,0), independent of END's ID. After an error the host discards/reset streams and starts a fresh activation.

# Design

The signed arithmetic is unchanged from Run 1: INT8 operands, INT16 products/biases, INT32 exact sums, magnitude-based ties-away rounding and signed saturation. Weights/biases are completely partitioned and both arithmetic dimensions are fully unrolled, expressing all 64 products per vector. Full CONFIG/PROCESS payload buffering, atomic configuration installation, validation-before-output, error precedence and activation-local validity/status are preserved.

The HLS output now uses supported `register_mode=both`; the input remains `off`. The generated output register slice owns pending beats and holds TVALID/data/sidebands until transfer. Adding that buffer alone is insufficient: internal write acceptance is not an external completed transfer. The synthesizable production wrapper counts only real external TVALID && TREADY edges and feeds that count internally to the HLS core via supported `hls::ap_none` Direct I/O. The core captures a baseline at activation entry, advances its expected count by each command's exact output length, and guards the **first input-header read** until that target has actually completed. Counter arithmetic is modulo unsigned 32 bits and at most 33 beats are outstanding, so wraparound does not alias another completion. No host protocol/AXI-Lite change is needed.

The guard must be attached to header reception. Separate polling loops were outlined/scheduled independently by this Vitis version: one trial deadlocked before issuing output, another allowed speculative next-header acceptance. The delivered source's guarded header read passes external sequencing tests under every readiness mode. Generated RTL is not patched, and the wrapper neither drives nor overrides TVALID; it observes actual handshakes and otherwise wires the specified ports through. **Integrate `qgemv`, not the bare `qgemv_core`.** See [HLS source](src/kernel.cpp), [production integration source](src/qgemv.sv), [retained native core](evidence/run2/synthesis/qgemv_core.v), and [native register slice](evidence/run2/synthesis/qgemv_core_regslice_both.v).

Compute and receive still request II=1. The command loop has no top-level II target. The C/native-core co-simulation supplies functional internal completion-count samples; it is not a timing model and is not used for external performance claims. The integrated DUT is independently driven/scored at its actual external pins for all fixtures, both without stalls and under backpressure. Only its no-stall port waveform supplies the throughput/latency measurements. No Python timing model exists.

All production-top protocol claims and performance measurements instead come from the integrated external-pin RTL suite with the actual hardware counter.
